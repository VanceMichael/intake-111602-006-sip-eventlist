# 资料服务接口

旧对话里包含完整版 0 和缺少中间版本的增量版 3；新对话从完整版 0 重新开始，旧对话通知仍能领取。MIME 正文与列表实例通过 Content-ID 关联。

通知采用 SIP 文本头和 multipart/related 正文，Content-ID 使用尖括号封装，RLMI cid 使用对应的无括号值。本地 /subscription 返回已授权对话和可读取的通知位置；仅模拟已建立对话内的接收，不连接真实电话网。

接收方必须按 Content-ID 把状态正文回填到 RLMI 的实例，不能按 multipart 中正文出现的先后配对：正文可以乱序、重复甚至缺失。一个实例的 `state="terminated"` 只是该实例结束，同一资源的其他实例或同一场馆的其他资源不受影响。

`fullState="true"` 是完整名单，`fullState="false"` 只是相对上一版的局部更新。增量不能作为一轮订阅的起点；版本必须连续，出现缺口时旧名单不能继续当作最新。订阅重建可能更换 Call-ID，旧对话的迟到通知不能覆盖新对话的名单。

本地服务的资料入口为 `/notify/1`。`fixtures/ordinary.json` 记录当前可预览的资料；`fixtures/transition.json` 保存资料源连续两个发布日期。调用 `POST /control` 并传入 `{"action":"advance"}` 推进发布日期，`inspect` 返回实际请求记录，`reset` 恢复本地源；控制入口不属于远端标准协议。来源分段、延迟和断连均可用场景条目的 `chunks`、`delayMs`、`disconnect` 配置，不需要依赖实际网络故障。

原件目录采用内容摘要寻址，接收凭据独立记录来源、媒体类型和预览结果。单份资料接收不表示来源范围已经读完，也不推断缺失资料的业务含义。
